1. Executive Summary
This PRD defines a production-ready, modular e-commerce platform built with Next.js and Supabase. The system includes a consumer storefront, customer self-service dashboard, moderator workspace, full admin panel, advanced product variation and inventory management, Cloudinary-backed media library, order tracking, courier automation, analytics, marketing integrations, finance reporting and operational controls.
The storefront should feel fast, clean, product-first and mobile-first, taking structural inspiration from the reference shopping experience: prominent search, campaign/offer sections, category and brand discovery, strong product cards, fast filters, variant selection, sticky mobile purchase actions and a friction-minimized checkout.
The back office should go beyond a basic store dashboard. It is designed as an integrated commerce operations system covering order management, customer management, inventory, shipping, marketing, fraud controls, reports, suppliers, costs, accounting and configurable business settings.
1.1 Primary Outcomes
Customers can discover, evaluate and purchase products quickly on any screen size.
Administrators can manage the entire catalog, content, media, orders, customers, couriers, campaigns and configuration without code changes.
Moderators can be given limited operational access through granular permissions.
Product variations are first-class inventory entities with individual SKU, price, stock and media.
Cloudinary is the centralized public media/CDN layer and is managed dynamically from the admin panel.
Orders have a visible status timeline and can synchronize with courier providers such as SteadFast and Pathao.
Business owners receive trustworthy sales, profit, cost, customer and operational reporting.
2. Goals, Non-Goals & Success Metrics
2.1 Product Goals
Create a conversion-focused storefront inspired by the reference website without copying protected visual assets or code.
Deliver a complete responsive experience for mobile, tablet and desktop.
Support a scalable catalog with categories, brands, attributes, variants, stock and promotional pricing.
Enable guest and account-based checkout with configurable payment and shipping methods.
Centralize business operations in a secure admin panel with RBAC and audit logs.
Provide modular integrations for couriers, SMS, analytics, Meta tracking and payment gateways.
Use a maintainable modular-monolith architecture that can later be split if scale requires it.
2.2 Non-Goals for V1
Native iOS/Android apps; the responsive web app will be mobile-first and PWA-ready.
Microservices from day one; unnecessary operational complexity should be avoided.
Full enterprise ERP/accounting compliance; V1 includes practical commerce finance tools, not a replacement for dedicated accounting software.
Automatic self-updating application binaries from the admin panel; deployments should remain CI/CD driven.

3. Product Principles & UX Direction
3.1 UX Principles
Product-first: reduce decorative UI that competes with products, prices, offers and actions.
Mobile-first: design mobile layouts intentionally instead of shrinking desktop screens.
Fast path to purchase: search, filters, add-to-cart, buy-now and checkout require minimal interaction.
Clear state: stock, price, sale, selected variant, delivery method and order status must always be obvious.
Progressive complexity: advanced tools stay in admin; customer UI remains simple.
Consistency: the same status vocabulary, button hierarchy, spacing and feedback patterns are reused throughout.
3.2 Visual Direction
Use a clean white/light background, strong typography, compact but readable cards, subtle borders/shadows, campaign banners, clear sale pricing and visually rich category/brand imagery. Animation should be subtle and functional. The admin panel should use a modern SaaS dashboard visual language distinct from the consumer storefront.

8. Cart, Checkout & Payments
8.1 Cart
Guest cart persists locally and can optionally be mirrored server-side.
Customer cart persists in database.
Guest cart merges into customer cart at login using deterministic conflict rules.
Cart lines reference exact variant IDs when a product has variants.
Recalculate price, coupon and availability server-side before checkout.
Support coupon, notes, quantity updates and shipping estimate.
8.2 Checkout Flow
Contact  -> Delivery address  -> Shipping method  -> Coupon / promotion  -> Payment method  -> Order summary  -> Place order
For Bangladesh-oriented commerce, checkout should prioritize name, mobile number, division/district/area/address and optional email. The field set must be configurable.

11. Reviews, Q&A, Loyalty & Retention
11.1 Reviews
1-5 star rating, title/comment, optional images/video.
Verified Purchase badge when review is tied to delivered order item.
Moderation states: pending, approved, rejected, spam.

Customers can ask questions on product pages. Moderator/admin can answer and publish. Optional customer email/SMS notification when answered.
11.3 Loyalty & Vouchers
Implement a configurable points ledger, not a mutable balance without history. Every earn/redeem/adjust/expire action creates a transaction. Rules may award points per spend, campaign or event and convert points to vouchers according to admin-configured rates.

Linked products and default purchase cost.
Payable/due balance and notes.
Future-ready for purchase orders without requiring full PO workflow in V1.
15.4 Due Manager
Track supplier dues, courier COD receivables and other approved outstanding balances with Due / Partial / Paid / Overdue states and transaction history.
15.5 Investor Manager
Admin-only module for investor identity, amount, date, terms/notes, withdrawals/profit-share transactions and uploaded documents. Access must be highly restricted and fully audited.
15.6 Accounting Manager
Provide operational accounting views for income, expenses, payable, receivable, courier COD receivable, supplier due, refunds and payment-gateway settlements. This module is not a substitute for statutory accounting software unless separately specified.

19. APIs, Integrations & Webhooks
19.1 Internal API Boundaries
Catalog service: products, variants, categories, brands, inventory reads.
Commerce service: cart, promotions, checkout, orders.
Media service: signed upload and metadata.
Courier service: provider adapters and webhook normalization.
Payment service: gateway adapters and webhook handling.
Marketing service: feeds, pixels/CAPI, campaigns.
Reporting service: pre-aggregated or query-optimized metrics.
19.2 Webhook Requirements
Verify signature/secret where provider supports it.
Store event ID and reject duplicates.
Use idempotent handlers.
Record provider response/error for operational troubleshooting.
Never trust webhook payload to bypass internal order/payment validation.
19.3 Integration Secrets
Cloudinary secret, courier keys, payment secrets, SMS credentials and Meta server tokens are server-side environment variables or encrypted settings. They must never be delivered to the browser.
20. Security, Privacy & Compliance
20.1 Security Requirements
Supabase RLS on all customer-sensitive tables.
Secure, httpOnly, sameSite cookies through supported auth flow.
Server-side Zod validation for mutations.
Rate limiting on login, OTP, order tracking, coupon validation and high-risk endpoints.
Webhook signature verification and idempotency.
Admin activity logging.
Least-privilege RBAC.
No service-role key in client bundle.
Protection against mass assignment and insecure direct object reference.
CSRF protections where applicable to chosen action pattern.
20.2 Privacy
Collect only data needed for order fulfillment, account, fraud prevention and marketing consent.
Marketing consent should be separate from required transactional communication.
Exports containing personal data require explicit permission.
Document retention and deletion rules should be configurable based on business/legal needs.

25. QA, Acceptance Criteria & Test Plan
25.1 Critical Acceptance Criteria
Guest can browse, search, filter, add variant to cart, complete checkout and track order without creating an account when guest checkout is enabled.
Customer can register/login, manage addresses, view own orders only, request returns and manage wishlist.
Moderator cannot access ungranted finance/settings pages by URL or API.
Admin can create a variable product, set per-variant SKU/price/stock/media, publish it and see correct storefront behavior.
Cloudinary upload uses signed server flow; deleted/replaced media remains synchronized with Supabase metadata.
Concurrent checkout cannot drive stock below zero.
Order status changes appear in customer timeline with timestamps.
Courier booking stores tracking IDs and webhook/status sync does not create duplicate events.
Payment webhooks are idempotent and cannot mark the wrong order as paid.
All key storefront pages pass responsive review at 320, 375, 430, 768, 1024 and 1440 widths.
Product/category/brand pages produce correct canonical metadata and structured data.
Admin data exports are permission-gated and do not leak service secrets.

Final architecture recommendation  Build V1 as a modular monolith: one Next.js application with clearly separated feature/service boundaries, Supabase for database/auth/RLS, and Cloudinary for media. This is easier to ship and maintain while preserving a clean path to future service separation.
